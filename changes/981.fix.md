**A Kimi planner that leaves the job's workspace unreadable is held as the planner's doing, not as a broken box.** When git could read the workspace before the planner's pass and cannot after it, for example because the planner ran `git init` in a subdirectory, the job is held saying that the workspace became unreadable during the planner's pass and that the planner is the likely cause, with git's own exit and words, and the hold declares the same cause as the hold for a planner that changed the workspace. It no longer declares an environment fault telling you to "Make git usable on this workspace in the box". A workspace git cannot read before the pass is still held as the environment, as before.
