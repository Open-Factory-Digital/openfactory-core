**The installer's preflight reaches Docker Desktop's daemon.** On macOS with Docker Desktop the preflight said the daemon did not answer, one step after the installer had pulled every image through it, and skipped the two checks that need it: the preflight's container was given the host socket's group, while Docker Desktop hands a container a socket owned by group 0. The installer now gives it the group a container sees, and a refused socket is named as a refusal, not as a daemon that gave no answer.
