**A deployment that runs on the agent token pool alone passes the installer's preflight.** The pool is `OPENFACTORY_AGENT_TOKENS`, which the worker reads first. The preflight did not know it. An upgrade of such a deployment was told that no agent credential was visible and was sent to replace a token that worked. Each harness now says which settings it authenticates with, and `openfactory preflight` and `openfactory doctor` both ask it. A pool that cannot be read is named as such, and so is the missing failover when a single token is left. A harness that signs in through its own login is no longer failed for a missing variable.
