**On Kimi Code, a planner stopped at the wall-clock wall now holds the job before the executor runs.** The wall stops only the shell the box started, so the stopped planner could keep writing into the workspace the executor then commits, and a file it wrote after the check had read the tree reached the pull request. The job is now held, naming the walled planner, before anything is pushed, and the workspace is discarded. This applies only to projects that turned `planner_stage` on.
